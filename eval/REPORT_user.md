# 真实用户说法评测报告

## 数据

- **来源**：10 位同学，每人写 10 句「想怎么调整日程 / 记录学习进度」，共 100 句。收集时**没有给任何例句**。
- **场景**：一位学生的一天（晨读、自习、背单词、专业课、网课、刷题、复习、背诵、错题复盘，当前时间 06:30），以及基础模板和 6 个学习项目（高数、英语阅读、真题、物理习题集、网课、文献阅读）。
- **标准答案**：产品可以修改任意一天的日程、基础模板和学习项目，并支持标记完成和昨日顺延。能力范围内的说法要解析完全正确；对象不明确的说法（「这个任务」「上午的学习」）、「进行中」这类状态、不是具体数字的进度，标准答案是**不做任何修改**，由产品追问或说明。按这个口径，100 句里 **60 句在能力范围内，40 句应当不改**。

## 用户想做的事

| 用户想做的事 | 句数 | 例子 |
|---|---|---|
| **跨天操作**（明天、周五、下周…） | **49** | 「把明天下午三点的复习挪到周五晚上」 |
| **标记完成 / 状态** | **19** | 「我的单词打卡今天完成了」 |
| **昨天没做完，顺延到今天** | **8** | 「昨天那个复习任务我没做完，顺延到今天」 |
| 进度不是具体数字 | 6 | 「网课看了三分之一」 |
| 说不清对象或时间 | 6 | 「这个任务先不做」「改九点多吧」 |
| 改今天的时间、记进度 | 12 | 「七点半改到九点」「网课看了两节」 |

用户是按「跨好几天的任务」来想计划的，所以产品支持跨天操作、标记完成和昨日顺延。日期由用户原话里的说法摘出，**换算成具体哪一天由规则完成**；跨天挪动拆成「原来那天删除 + 目标那天新增」，两天各自按规则排程；预览里标明每一项落在哪一天，撤销时一起恢复。

## 结果

| | DeepSeek | 本地规则 |
|---|---|---|
| 能力范围内全对 | **52 / 60（86.7%，95% 置信区间约 76%–93%）** | 39 / 60（65%） |
| 应当不改时不乱改 | **37 / 40（92.5%，约 80%–97%）** | 35 / 40（87.5%） |
| **总计处理正确** | **89 / 100** | 74 / 100 |

按类别（DeepSeek）：跨天操作 26 / 31，标记完成 8 / 9，昨天顺延 8 / 8，记进度 6 / 6，改时间 4 / 5。

**DeepSeek 在能力范围内的 8 条失败，全部是「没有改动」，没有一条改错。** 其中 6 条是它主动反问（「周末是周六还是周日？几点？」「是不是指错题复盘？」），2 条是「改到晚上」没说具体时间、被校验拦下。这类失败对用户是安全的，只是多了一轮对话。

## 底线检查

模型的理解结果都要先过规则层的四条检查，不通过就不执行：

| 检查 | 防止什么 |
|---|---|
| 提到其他日子、但没有指令带日期 → 不执行 | 把「明天的」套到今天或模板上 |
| 记进度时句子里没有具体数量 → 不执行，改为说明 | 「今天单词背完了」被编成「英语阅读 +1」 |
| 句子说的是将来某天 → 不记进度 | 「后天刷两套真题」是安排，不是做完了 |
| 句子里有「没 / 未」→ 不标记完成 | 「上午的单词没背」被标成完成 |

日期检查的效果，在同一批 100 句上对比：

| | 不加日期检查 | 加日期检查 |
|---|---|---|
| DeepSeek · 88 句跨天、顺延等说法被误改 | 35 / 88（40%） | **15 / 88（17%）** |
| DeepSeek · 其中跨天操作不乱改 | 32 / 49 | **47 / 49** |
| DeepSeek · 其中昨天顺延不乱改 | 2 / 8 | **8 / 8** |
| 能力范围内的句子被误拦 | — | **0** |

## 应当不改却改了的 3 条

- #23「明天上午的学习取消哈」→ 删掉了明天上午的 4 项学习。标注为「需要追问」，但这样理解也说得通，**有争议**。
- #35「周三下午没空，学习计划换到晚上七点」→ 挪动名为「学习」的一项；规则在周三找不到叫「学习」的活动，实际不会改动，按解析口径算错。
- #60「还剩一节网课没看完」→ 网课进度 +1。句子里有「一节」，数量检查没有拦住。

## 种子集复测

同一版本在 60 条种子用例上：DeepSeek 57 / 60，本地规则 50 / 60。
