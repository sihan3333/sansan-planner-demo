# 三三作息簿 App 设计文档

- 日期：2026-10-26
- 状态：草稿，待确认
- 产出：本设计文档 → PRD（按用户的 7 部分模板）→ Figma 原型。本次不改网页代码

## 1. 为什么做

三三作息簿现在是网页：用基础模板生成每天的时间轴，一句话改日程，跟踪学习项目进度。两个问题：

1. **形态不对。** 日程是随身的事，网页在手机上只是缩小的页面：到点不会提醒，不能在通知里打勾，桌面上看不到「现在该做什么」。
2. **AI 用得少。** AI 只做一件事：把一句话翻译成改日程的指令。「发现了几件事」是规则统计，不是 AI。

用户对 App 的定位（原话）：**记录我的日程，优化我的日程，帮我安排。**

## 2. 目标、非目标、反目标

**目标**

1. 做成手机 App，围绕「记录 → 优化 → 安排」形成闭环，AI 在每一环都有实际作用。
2. 记下「实际做了什么」，而不只是「计划做什么」，作为优化的数据基础。
3. 16 项 AI 功能全部写入 PRD，分三期，每项标明版本和优先级。

**非目标**

1. 不做多人协作、共享日历、团队排班。
2. 不做健康数据接入（睡眠、步数），也不做医疗建议。
3. 本次不写 App 代码，不改网页版。

**反目标：出现这些就算失败**

1. **AI 不经确认就改日程。** 所有改动沿用网页版「先预览再写入、可撤销」。
2. **推送打扰。** 一天的提醒多到用户关掉通知，App 就失去意义。
3. **记录变成负担。** 让用户每件事手动填开始和结束时间，没人会坚持。
4. **未经同意上传数据，或另作他用。** 默认存本地，上传都要先征得同意。

## 3. 原则：模型理解、规则决定

沿用网页版的分工：

1. **模型**：读懂一句话、语音、截图；把统计结果解释成人话；提出建议。
2. **规则**：时间怎么排、冲突怎么让、每天目标怎么算、提醒什么时候发。
3. **用户**：任何改动都先看预览，确认才写入，7 秒内可撤销。

## 4. 方案选择

| 方案 | 取舍 | 结论 |
|---|---|---|
| **A. 跨平台 App + 原生扩展** | Flutter 或 React Native 写主体，桌面小组件、通知交互按 iOS / Android 原生写；16 项功能都能做，开发量最大 | **用户选定** |
| B. 网页套壳 PWA | 复用代码最便宜；iOS 不支持小组件，通知回复和后台提醒不可靠，V1.0 核心做不成 | 排除 |
| C. 微信小程序 | 打开方便；推送需每次授权，无小组件，后台受限 | 排除 |

网页版保留，作为电脑上编辑模板和学习项目的入口。

## 5. 功能与分期（用户确认）

| 版本 | 主题 | 功能 |
|---|---|---|
| **V1.0** | 记下实际，替你安排 | ① 计划 vs 实际　② 语音随手记　③ 一句话排一天　④ 任务收件箱　⑤ 被打断一键重排　⑥ 通知里直接回复　⑦ 桌面小组件 |
| **V1.1** | 用你的数据优化 | ⑧ 复盘写成人话　⑨ 精力时段　⑩ 时长校准　⑪ 目标可行性　⑫ 每周报告 |
| **V1.2** | 更省事的录入与长期目标 | ⑬ 截图导入　⑭ 每晚 1 分钟复盘　⑮ 目标拆解　⑯ 专注计时 |

分期依据：V1.1 依赖 V1.0 攒下的至少 2 周实际数据；V1.2 锦上添花，不影响主流程。

现有能力全部保留：时间轴、基础模板、学习项目、打勾推进度、一句话改日程（含跨天、标记完成、顺延）、发现了几件事。

### 5.1 每项功能怎么分工

| 功能 | 用户怎么用 | AI 做什么 | 规则做什么 |
|---|---|---|---|
| ① 计划 vs 实际 | 到点通知问「开始了吗」，点开始 / 跳过 / 晚点；结束时点完成 | 不参与 | 记录实际开始、结束时间；没响应的不猜，标为「没记录」 |
| ② 语音随手记 | 说「刚才组会多开了半小时」 | 把话转成对实际记录的修改 | 改实际时间，后面的安排按顺延规则让位，先预览 |
| ③ 一句话排一天 | 「明天复习考试、取快递、健身」 | 拆成任务和预计时长 | 找空档排进去，冲突按现有优先级让位，先预览 |
| ④ 任务收件箱 | 想到就丢进去，可带截止日 | 估计时长、判断类别 | 按截止日和空档给出放哪天哪段的建议，用户一键接受 |
| ⑤ 被打断一键重排 | 按「我被打断了」，选耽误多久 | 不参与 | 沿用网页版顺延规则 |
| ⑥ 通知里直接回复 | 在通知上回一句话 | 同一句话改日程 | 同上；改动在 App 内留有撤销入口 |
| ⑦ 桌面小组件 | 桌面看「现在该做」「下一项」，可直接打勾 | 不参与 | 读当前时间轴 |
| ⑧ 复盘写成人话 | 看每周或每天的解读 | 把统计结果写成人话，给出可能原因，标明是推测 | 统计完成率、偏差 |
| ⑨ 精力时段 | 看自己的高效时段，一键把难的学习挪过去 | 解释 | 按打勾时间和完成率算高效时段 |
| ⑩ 时长校准 | 新增任务时提示「同类平均 1.6 小时」 | 判断任务属于哪一类 | 用实际记录算平均时长 |
| ⑪ 目标可行性 | 新建学习项目时提示能不能按期完成 | 不参与 | 用实际可用时间算 |
| ⑫ 每周报告 | 每周一看上周小结和下周模板建议 | 写小结、提建议 | 统计；建议采纳前先预览 |
| ⑬ 截图导入 | 截课表、群通知、作业要求 | 读出时间和事项 | 换算日期、排进去，先预览 |
| ⑭ 每晚 1 分钟复盘 | 晚上回答 2–3 个问题 | 提问并整理成当天小结 | 控制只在设定时间问一次 |
| ⑮ 目标拆解 | 「三个月雅思到 7 分」 | 拆成学习项目和每日任务草稿 | 按截止日算每天目标；用户确认后才建 |
| ⑯ 专注计时 | 开始学习时计时，可暂停 | 不参与 | 结束时记实际时长，关联学习项目自动推进度 |

### 5.2 推送规则（防打扰）

1. 只有用户标记「需要提醒」的活动才推送；默认只给学习、工作和带截止的任务提醒。
2. 每天推送上限默认 8 条，可调；睡眠时段不推送。
3. 连续 3 次不响应同一类提醒，App 主动问要不要关掉这类提醒。

### 5.3 实际时间怎么记全（设计时替用户拿的主意）

推送上限和「计划 vs 实际」会互相卡住，所以记录不全靠推送：

1. **一个活动只推 1 条。** 开始时推「开始了吗」；结束不单独推，下一条提醒顺带问上一项做完没有。
2. **没有提醒的活动**：打开 App、看桌面小组件时都能一键打勾；每天晚上推 1 条「今天的核对」，把没记录的活动列成一张清单，批量勾选做了、没做、改了时间。
3. **仍然没记录的不猜**，标为「没记录」，不计入优化统计；V1.1 的统计只用有记录的数据，并在报告里写明覆盖了多少。

### 5.4 其他设计时替用户拿的主意

1. **目标用户**：有固定作息、同时推进长期学习目标的学生和刚工作的人。与现有 100 条真实说法的来源（10 位同学）一致。
2. **数据与网页版**：V1.0 的 App 独立可用，App 内就能编辑基础模板和学习项目，数据存手机本地，不需要账号。和网页版互通放到 V1.1，开启云同步时才需要登录，冲突时以最后修改为准，并在 App 里列出被覆盖的改动。
3. **埋点**：只上传匿名事件，首次启动时说明并征得同意，用户不同意就只在本机统计。上传内容不含日程原文，指令原话也要单独同意才上传，用于评测。
4. **原型平台**：按 iOS 规范画，小组件和通知按 iOS 的样子；PRD 写明 Android 上的差异。
5. **语音和截图识别**：语音用手机系统自带的语音识别，转成文字后才发给模型；截图用通义千问 VL，经同一个 Worker 中转，和安心药箱拍照核对用的是同一个接口，截图不保存。
6. **Figma**：在现有文件第 3 页生成，复用安心药箱插件的写法，样式和颜色另起一套。

## 6. 视觉与原型

1. **视觉**：沿用网页版的墨绿、米色主色和衬线体日期，分类色沿用网页版 8 种分类色，看起来是同一个产品。设计时的取值：主色 `#6B9136`，背景 `#FAF6E8`，文字墨绿 `#152009`；深色模式见网页版变量。
2. **原型工具**：Figma，用插件代码生成，和安心药箱同样的做法。Figma 免费版一个文件最多 3 页，现有文件已用 2 页，第 3 页给作息簿 App。
3. **原型范围**：V1.0 画完整流程；V1.1、V1.2 画关键屏，约 20 屏。

| 版本 | 屏 |
|---|---|
| V1.0 | 今天（时间轴 + 现在该做 + 一句话输入）、到点通知、计划 vs 实际、晚间核对、一句话改日程预览、语音随手记、一句话排一天、任务收件箱、被打断一键重排、通知里直接回复、桌面小组件、基础模板、学习项目、首次使用与数据授权 |
| V1.1 | 每周报告、精力时段、时长校准与目标可行性 |
| V1.2 | 截图导入、每晚复盘、目标拆解、专注计时 |

## 7. 数据与隐私

1. 数据默认存手机本地；云同步可选，开启时说明同步什么。
2. AI 请求经现有 Cloudflare Worker 中转，密钥不在 App 里；只发送这一句话和必要的日程片段。
3. 截图、语音只用于这一次识别，不保存原件。

## 8. PRD 结构

按用户给的 7 部分模板：需求背景、需求概述、功能清单、需求详情（交互逻辑、功能详述）、数据埋点、数据集要求、验收标准。功能清单标明 V1.0 / V1.1 / V1.2 与 P0–P2。AI 相关功能写清评测方式，并引用现有的指令解析评测（100 条真实说法）。
